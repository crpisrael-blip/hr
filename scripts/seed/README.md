# דאטה ניסיונית לבדיקות עומס

כלי פיתוח **נפרד לחלוטין מקוד התוכנה** — לא חלק מהבנייה, לא מ-CI, ולעולם לא רץ
בייצור. מייצר נתונים סינתטיים בהיקף הייצור של הלקוחה כדי לבדוק ביצועים ולתת
מגרש משחקים אמיתי למנוע ההתאמה (AI).

## מה נוצר (בברירת מחדל של `--full`)

| ישות | כמות | הערות |
|---|---|---|
| חברות | ~180 | כולן עם **הסכם עמלה זהה** (8.333%, חודשי, אחריות 90 יום) |
| משרות | ~700 | כל אחת עם דרישות (חובה/יתרון), **תחום**, מיקום, היקף ושכר |
| מגייסים / צוותים | ~25 / 8 | הבעלות מפוזרת ביניהם (לבדיקת סינון פר-מגייס) |
| מועמדים | ~80,000 | כולל "ישנים" (תאריכי יצירה עד ~4 שנים אחורה) |
| קורות-חיים | ~80,000 | רשומת מסמך + **ניתוח AI מדומה** (`document_analyses`) לכל מועמד |
| מועמדויות | ~80,000 | מועמדות אחת לכל מועמד מול משרה פתוחה, בשלבים שונים |

הנתונים סינתטיים לגמרי (שמות/מיילים/טלפונים מזויפים) ובני-שחזור (RNG עם seed
קבוע — אותה דאטה בכל הרצה).

## דרישות מקדימות

1. **פרויקט Supabase נפרד לבדיקות** (לא הייצור!). זול/חד-פעמי.
2. הסכימה מוחלת עליו — הריצו את `supabase/schema.sql` פעם אחת ב-SQL Editor,
   או `supabase db push`. חייב לכלול את מיגרציית `0037` (שדה `app.job_field`).
3. `DATABASE_URL` של אותו פרויקט (Dashboard → Database → Connection string).

## הרצה

```bash
# שלב קטן קודם (~5,000 מועמדים) — לוודא שהכול עובד:
DATABASE_URL='postgres://...staging...' ./scripts/seed/run-seed.sh

# נפח מלא (~80,000 מועמדים):
DATABASE_URL='postgres://...staging...' ./scripts/seed/run-seed.sh --full
```

- הסקריפט **חוסם** `DATABASE_URL` שמצביע על פרויקט הייצור, ומבקש אישור לפני טעינה.
- לדילוג על האישור: `--yes`. לכוונון כמויות: `N_CANDIDATES=20000 ... run-seed.sh`.
- הטעינה set-based ומהירה (שניות עד דקות בודדות גם ב-80k).

## קורות-חיים אמיתיים (אופציונלי, לבדיקת מסלול ה-AI)

הדאטה מייצרת **טקסט קו״ח סינתטי** (ב-`document_analyses`) — מספיק למנוע ההתאמה.
כדי לבדוק גם את **החילוץ בפועל** (`analyze-cv`), העלו 20–50 קבצי PDF/DOCX אמיתיים
דרך המערכת עצמה: כרטיס מועמד → **"+ העלאת קו״ח"** → **"נתח ב-AI"**. אין צורך בסקריפט.

## ניקוי

הדאטה הניסיונית מזוהה בסמנים ייחודיים, כך שאפשר למחוק אותה בלי לפגוע בנתונים
אמיתיים (כמו חשבון המנהלת שיצרתם):

```bash
DATABASE_URL='postgres://...staging...' psql "$DATABASE_URL" -f scripts/seed/unseed.sql
```

לניקוי מלא לגמרי — פשוט אפסו/מחקו את פרויקט הסטייג׳ינג.

## קבצים

- `seed.sql` — המחולל (פרמטרי, בר-שחזור).
- `run-seed.sh` — עטיפה עם חסימת ייצור ואישור.
- `unseed.sql` — מחיקת הדאטה הניסיונית בלבד.
