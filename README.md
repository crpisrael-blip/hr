# HR — מערכת גיוס והשמה

אתר ציבורי עם משרות והגשת מועמדות, אזור אישי למועמדים, וממשק פנימי לניהול הגיוס, הלקוחות, המשימות והכספים.

האפיון המלא: [`docs/SPEC.md`](docs/SPEC.md) (גרסה 0.8).

## מודל המידור

שלושה אזורי אמון, שלוש כתובות, שלוש פריסות נפרדות. אין קוד משותף בין הבנדלים.

| אזור | כתובת | גישה למסד |
|---|---|---|
| ציבורי | hr.ort-tech.co.il | אין. HTML סטטי; המשרות נצרבות בזמן בנייה |
| מועמדים | my.hr.ort-tech.co.il | דרך שכבת ה-API, בהיקף החשבון בלבד |
| צוות | app.hr.ort-tech.co.il | דרך שכבת ה-API, לפי מטריצת ההרשאות |

ההרשאות נאכפות בשכבת ה-API בנקודה אחת. RLS במסד הוא רשת ביטחון שנייה.

## מבנה

```
docs/SPEC.md              האפיון. מקור האמת לכללי העסק
```

## המיגרציות

| קובץ | תוכן |
|---|---|
| `0001_foundation` | סכמות, טיפוסים, עובדים, מטריצת הרשאות, יומן ביקורת |
| `0002_crm` | חברות, אנשי קשר, הסכמים מסחריים, משרות, פרסומים |
| `0003_candidates` | מועמדים, מסמכים, מועמדויות, ראיונות, האזור האישי |
| `0004_tasks` | משימות, תבניות, תהליכים, אוטומציות, תזכורות |

## הרצת בדיקות

```bash
npm run db:test
```

מקים Postgres זמני, מריץ את כל המיגרציות ואז את בדיקות כללי העסק. דורש `postgresql-16` מותקן. מול מסד קיים:

```bash
DATABASE_URL=postgres://... npm run db:test
```

הבדיקות מאמתות בין השאר את דוגמת הבונוס שבאפיון (חמש השמות, שני יעדים, תוצאה 1,800), את פיצול ההשמה החוצה גבול מדרגה, ואת השוואת סכום לוח התשלומים לעמלה.

## מוסכמות

- סכומים כספיים ב-`numeric`, לעולם לא נקודה צפה. עיגול לאגורה בסוף החישוב בלבד.
- נתון לא ידוע נשמר כ-`null`, לא כאפס.
- ההרשאות, חשיפת השלבים, כללי האוטומציה וההסכמים הם נתונים הנערכים מהמערכת, לא ערכים בקוד.
- יומן הביקורת ניתן להוספה בלבד.
