## חלק א — מסד נתונים, RLS ופונקציות קצה


**מתודולוגיה:** נקראו כל 21 המיגרציות, `schema.sql`, הבדיקות, שתי פונקציות הקצה ותבניות המייל. הורץ בפועל `scripts/db-test.sh` על Postgres 16.13 מקומי (cluster חד-פעמי): **כל 21 המיגרציות ושני קובצי הבדיקה עברו**. לאחר מכן הורצו שאילתות קטלוג ו-PoC בסיסי SQL; ממצאים המסומנים **[אומת בהרצה]** הודגמו בפועל. `supabase/schema.sql` זהה בית לבית לשרשור המיגרציות (אין drift).

### קריטי

**C1. כל משתמש מחובר (כולל מועמד) יכול להפוך את עצמו ל-superadmin דרך `app.link_employee` [אומת בהרצה]**
`0008_rls_access.sql:60-76` (הפונקציה), `0017_public_form_access.sql:17` (`grant execute on all functions in schema app to authenticated`).
`link_employee(p_email, p_name, p_role)` היא `SECURITY DEFINER`, אינה בודקת מי הקורא, מקבלת `p_role` חופשי, ומוענקת ל-`authenticated`. נועדה להרצה ידנית מ-SQL Editor אך חשופה דרך `POST /rest/v1/rpc/link_employee` לכל מי שיש לו JWT — כלומר כל מועמד שנכנס ל-my.hr עם OTP.
תרחיש: מועמד מבצע `supabase.rpc('link_employee', {p_email: '<המייל שלו>', p_name: 'x', p_role: 'superadmin'})` → נוצרת שורת `employees` עם ה-`user_id` שלו → גישה מלאה לכל המועמדים, הכספים, `employee-docs`. בגלל `on conflict (email) do update ... role = excluded.role` הוא יכול גם **להוריד את המנהלת ל-recruiter**.
```sql
revoke execute on function app.link_employee(text,text,app.user_role) from public, anon, authenticated;
```

**C2. מדיניות `staff_all` נותנת לכל מגייס CRUD מלא על 48 טבלאות — כולל תפקידו שלו, הגדרות והרשאות [אומת בהרצה]**
`0008:35` (`grant select, insert, update, delete on all tables in schema app to authenticated`), `0008:41-52`.
PoC כ-`authenticated` עם `user_id` של מגייס: `update app.employees set role='manager' where user_id = auth.uid()` → `UPDATE 1`; `is_manager()` הפך ל-`true`; `select from finance.bonus_plans` עבר; `update app.settings set value='["*/*"]' where key='files.allowed_mime'` → `UPDATE 1`; `update app.permission_defaults` → `UPDATE 6`.
תיקון מינימלי: טריגר `guard_employee_privileges` שחוסם שינוי `role/employment_status/user_id` למי שאינו `is_manager()`; מדיניות `is_manager()` בלבד על `settings`, `permission_*`, `agreements`, `stage_exposure`, `automation_rules`, `teams`, `job_publications`; `revoke delete on all tables in schema app from authenticated`.

**C3. אין שכבת API — מטריצת ההרשאות היא נתונים מתים ו-RLS הוא קו ההגנה היחיד**
`docs/SPEC.md:80,133,555` מול `apps/team-app/src/lib/supabase.ts`. אף קוד לא קורא את `permission_defaults`/`permission_profile_rules`/`permission_overrides`. היקפי "שלי/צוות/הכל", הסתרת שדות רגישים, שלילה פר משתמש — לא נאכפים. `0008:2-3` מודה ("תיאכף בשכבת ה-API בהמשך").
תיקון: להחליט — (א) RLS מודע-היקף עם `app.effective_scope(module, action)`; או (ב) Edge Functions כ-API יחיד ו-`revoke` של גישת PostgREST הישירה.

**5. SignaturePad — החתימה נמרחת בהיסט במסכי מובייל; אין חלופה למקלדת**

```ts
};
```
